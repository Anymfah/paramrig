# Prompt 1 : les fondations de l'éditeur 3D

> Document autonome : un agent qui démarre sans contexte doit pouvoir l'exécuter de bout en bout. Le plan maître est `docs/scene-editor-plan.md` ; lis-le d'abord, ses décisions d'architecture (section 3), son modèle (section 4), sa carte des modules (section 5) et ses principes de manipulation (section 7, avec la définition de « fini ») s'appliquent ici sans exception. L'état de référence est le code, pas les documents.

Dépôt : `/Users/soheil/Documents/repos/paramrig`, branche `main`. ParamRig est un workbench où une IA construit des rigs paramétrés (`src/rigs/`, `src/workspace/`) qu'un humain règle avec des contrôleurs. L'éditeur vectoriel (`src/vector/`) est l'un des renderers ; ce prompt en crée un second, l'éditeur de scène 3D (`src/scene/`), qui reprend Blender. Ce premier prompt livre tout ce qui précède l'édition de maillage : le viewport, la navigation, le mode objet complet, les transformations, l'outliner, les propriétés, l'historique, les fichiers et le harnais de QA.

## Règles, toutes obligatoires

Avant tout `docker compose up`, `docker compose ls` ; si `stellary`, `helios`, `site-anym` ou un autre stack de développement tourne, n'en démarre et n'en arrête aucun (`stellary-ci` peut rester). Le stack `paramrig` est en général déjà lancé et recharge à chaud. Port fixe 5174.
- **Vérification avant chaque commit**, dans cet ordre, toutes vertes :
  ```bash
  docker compose run --rm app npm run typecheck
  docker compose run --rm app npm run lint
  docker compose run --rm app npm test
  docker compose run --rm app npm run e2e -- scene-
  git diff --check
  ```
- **Git** : commits fréquents sur `main`, messages qui décrivent le comportement, pas de push, pas de branche, pas de stash, pas de `git checkout` destructif (d'autres agents partagent le working tree). Termine chaque message de commit par `Co-Authored-By: <ton nom de modèle> <noreply@anthropic.com>`.
- **Dépendances** : `three@0.180` et `@types/three` sont installés. Ajoute `three-mesh-bvh` (version compatible avec three 0.180, vérifie le `peerDependencies`) via `docker compose run --rm app npm install three-mesh-bvh@<version>`. Rien d'autre dans ce prompt. `@react-three/fiber` reste pour les rigs existants ; l'éditeur ne l'utilise pas.
- **Direction artistique** : palette ParamRig (`src/styles/tokens.css`), tokens `--scene-*` en tête de `src/styles/scene.css` (importée dans `src/main.tsx` à côté des quatre feuilles existantes), thème clair équivalent, `prefers-reduced-motion` et `forced-colors` respectés. Pas de bleu Figma, pas de style « dashboard ». Aucun contrôle natif : pas d'attribut `title`, pas d'`alert` / `confirm`, pas de `<select>` ni de `<input type=range>` non stylés. Réutilise `src/ui/` (`Button`, `IconButton`, `Tooltip`, `NumberField`, `ColorField`, `SelectField`, `SwitchField`, `SliderField`, `ContextMenu`, Radix `DropdownMenu` / `Popover` avec les classes `menu`, `menu__item`, `popover`). Cibles de pointeur d'au moins 32 px, 44 px en pointeur grossier (`src/ui/hit-target.ts`), glyphe visuel plus petit ; cela vaut aussi pour les poignées de gizmo dans le viewport.
- **Texte** : `user-select: none` sur le chrome, `user-select: text` dans les champs et valeurs. Wording produit en anglais, « sentence case », sans point d'exclamation, sans « real / true / no fake ». Les libellés reprennent ceux de Blender quand ils existent (« Adjust last operation », « Frame selected », « Set origin »).
- **Historique** : une geste continue de pointeur = une entrée d'undo, avec libellé (`src/vector/history.ts`, déplacé en `src/editor/history.ts` au chantier 1). Pendant la geste on écrit avec `record = false` ; Escape restaure l'état de départ. Un clic sans mouvement n'écrit jamais dans l'historique.
- **Viewport** : three.js sans React à l'intérieur, rendu à la demande, monté une seule fois (voir la section 3 du plan). Toute donnée haute fréquence (position du curseur, i/s, delta de transformation) reste hors de tout contexte React : le HUD est une feuille qui lit une ref. Chargé paresseusement (`lazy`) et enveloppé dans `RendererErrorBoundary` pour qu'un échec WebGL n'emporte pas le reste de l'application ; l'échec affiche un `StatusMessage` explicite dans la scène.
- **Touches** : table dans `src/scene/keymap.ts`, sur `event.code` pour lettres et chiffres (AZERTY : la rangée `& é " '` donne `Digit1…4`), `event.key` pour la saisie numérique. ⌘Z / ⇧⌘Z et ⌃Z / ⇧⌃Z ; jamais ⌘W, ⌘T, ⌘N, ⌘Q. Les touches sont ignorées quand un champ a le focus, sauf Escape. Le listener du viewport est enregistré avant celui de la page et arrête la propagation de ce qu'il possède.

## Chantier 7 · Transformations modales et gizmos

- `src/scene/transform/session.ts` (pur) : `beginTransform({ mode: 'move' | 'rotate' | 'scale' | 'trackball', targets, pivot, orientation, view, cursorStart })`, `update(session, { cursor, modifiers, keys })`, `confirm`, `cancel`. - `src/scene/transform/math.ts` : projection du curseur sur un plan / une droite, angle autour du pivot, rapport d'échelle, compositions Euler stables (pas de saut à ±180°), décomposition matrice → position / rotation / échelle.
- Dans le viewport : G / R / S lancent une session sur la sélection ; clic gauche ou Enter confirme, clic droit ou Escape annule ; la session prend le Pointer Lock et dessine son propre curseur dans l'overlay, pour un déplacement sans butée comme le « wrap » de Blender (refus du verrouillage : session sans wrap, jamais de saut) ; le HUD suit le curseur ; une ligne pointillée relie le pivot au curseur pendant rotation et échelle ; les axes contraints se dessinent en couleur d'axe à travers toute la vue.
